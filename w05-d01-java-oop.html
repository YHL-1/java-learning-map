01 / ENVIRONMENT

JDK、JRE、JVM：三个同心圆

先纠正一个常见误解：它们不是"并列的三个东西"，而是层层包含。面试问"三者区别"，答的是包含关系 + 各自职责，不是背定义。

JDK
Java Development Kit · 开发工具包
javac / javadoc / jar / jps / jstack / jmap / jconsole
JRE
Java Runtime Environment · 运行环境
核心类库 java.base、java.sql、java.net…
JVM
执行字节码
屏蔽操作系统差异

一句话说清各自职责

JVM一份规范（虚拟机指令集、内存模型），HotSpot 是它的主流实现。负责加载 .class、管理内存、执行字节码。它自己是平台相关的——Windows 版和 Linux 版是两个程序。
JRE= JVM + 标准类库。你写的 String、List 不在 JVM 里，在类库里。
JDK= JRE + 开发工具。装了 JDK 就不用单独装 JRE——它包含 JRE。

所以"Java 跨平台"到底跨的是什么？

跨的是字节码，不是 JVM。同一份 Hello.class，在 Windows 的 JVM 和 Linux 的 JVM 上都能跑；但 JVM 本身要为每个操作系统单独编译一份。
这就是 "Write Once, Run Anywhere" 的真实含义：源码/字节码一次编写，靠各平台的 JVM 各自承接。

版本与字节码版本号

面试常问"Java 8 和 Java 17 的区别"，也可能问 class 文件的版本号。记住这条线：

JDK 版本class 文件版本地位
Java 852历史分水岭（Lambda / Stream 诞生），存量系统最多
Java 1155LTS，开始去 JRE 化
Java 1761LTS，Spring Boot 3 的最低要求
Java 2165LTS，虚拟线程正式落地

延伸问题：为什么从 JDK 11 开始不再单独发布 JRE 了？

因为 jlink 可以按需裁剪出只包含所需模块的运行时镜像（自定义 JRE），通用 JRE 的存在意义变小。面试答到"模块化 + jlink 裁剪"即可，不必展开。

javac 内部做了什么

  1. 词法分析：把字符流切成 Token（public、class、标识符…）。
  2. 语法分析：Token 组成抽象语法树 AST，语法错在这里报（少个分号）。
  3. 语义分析：类型检查、符号表解析、泛型擦除。类型不匹配在这里报。
  4. 字节码生成：AST 翻译成 JVM 指令集，写出 .class（含常量池、方法表、字段表）。

类加载五个阶段

加载读取 .class 二进制，生成 Class 对象放进堆
验证文件格式、元数据、字节码合法性检查
准备静态变量分配内存 + 赋零值（不是代码里的初值！）
解析符号引用 → 直接引用
初始化执行 <clinit>，静态变量赋真值、执行 static 块

高频陷阱

static int a = 1; 在准备阶段 a 是 0，到初始化阶段才变成 1。
所以"静态变量什么时候赋值"要分两阶段答，直接说"类加载时赋值"会被追问。

解释执行 vs JIT 编译

JVM 执行字节码时先解释（逐条翻译，启动快、执行慢），同时统计每个方法/循环的调用次数；超过阈值（热点代码）就交给 JIT 编译成本地机器码并缓存。

  • C1：编译快、优化浅，适合快速启动。
  • C2：编译慢、激进优化（内联、逃逸分析、锁消除），适合长期运行。
  • 两者共存叫分层编译（Tiered Compilation），Java 8 之后默认开启。

一句话答面试

"Java 先由 javac 编译成与平台无关的字节码，运行时由 JVM 解释执行；热点代码再经 JIT 编译为机器码。所以它兼具编译型和解释型的特征。"

04 / PASS BY VALUE

这是 D1 最容易被问倒的一题。结论先给：实参的值被复制一份传给形参。基本类型复制"值"，引用类型复制"地址"。所以——能改对象内容，但换不掉对象本身。

场景 B：传对象时，到底复制了什么？

难点在这。void change(Order o) 传进去的，是地址的副本（值传递依然成立）。所以会产生两种截然不同的结果：

// ① 修改对象内容 → 调用方能看到（因为两个引用指向同一个堆对象）
void setAmount(Order o) {
    o.amount = 100;        // 顺着地址改堆里的数据 → 生效
}

// ② 重新赋值引用 → 调用方看不到（只是让副本指向了新对象）
void replace(Order o) {
    o = new Order(999);   // 只改了副本 o 的指向 → 无效
}

能生效

o.setXxx()、list.add()、arr[0]=1
都是"顺着地址改堆里的内容"。

不生效

o = new ...、s = "other"
都是"改副本的指向"，原引用纹丝不动。

那 String 为什么改不了？

双重原因叠加：① 引用是副本；② String 是不可变对象，任何"修改"都返回新对象。所以 void f(String s){ s = s + "!"; } 对外部毫无影响。

面试标准答法（背这段结构）

"Java 中方法参数传递只有值传递。基本类型传递的是值的副本；引用类型传递的是引用（地址）的副本，因此方法内可以通过这个副本修改原对象的状态，但无法让原引用指向新对象。所谓'引用传递'的说法不准确。"

追问：那怎么实现真正的交换？

  • 返回数组 / 返回 Pair：int[] swap(int a, int b){ return new int[]{b,a}; }
  • 交换对象里的字段（对象是可变的话）
  • 用成员变量或容器承载结果
  • Java 没有 C# 的 ref / C++ 的 &，语言层面做不到

05 / OOP

封装、继承、多态

三个词都认识，但面试考的是细节：重写的规则、构造器的顺序、字段为什么不参与多态、动态分派发生在什么时候。

封装：不是"加 getter/setter"

封装的本质是把"状态"和"对状态的合法操作"绑在一起，并且只暴露必要入口。无脑生成 getter/setter 只是把 public 字段换了个写法，等于没封装。

public class Order {
    private final BigDecimal amount;   // 私有 + final：外部不能乱改

    public Order(BigDecimal amount) {
        if (amount == null || amount.signum() < 0) {
            throw new IllegalArgumentException("金额不合法");  // 构造时校验
        }
        this.amount = amount.setScale(2, RoundingMode.HALF_UP);
    }
    public BigDecimal getAmount() { return amount; }
}

封装的收益：合法状态只能通过构造器/方法产生，非法值在入口就被挡住，而不是散落在业务代码里靠调用方自觉。

继承：构造器的执行顺序

这点几乎每场面试都问。顺序是：父类静态块 → 子类静态块 → 父类实例块 → 父类构造器 → 子类实例块 → 子类构造器。静态块只在类初始化时执行一次。

class A {
    static { System.out.println("A 静态块"); }
    { System.out.println("A 实例块"); }
    A() { System.out.println("A 构造器"); }
}
class B extends A {
    static { System.out.println("B 静态块"); }
    { System.out.println("B 实例块"); }
    B() { System.out.println("B 构造器"); }
}
// new B() 输出：A 静态块 → B 静态块 → A 实例块 → A 构造器 → B 实例块 → B 构造器

重写（Override）的五条规则

两同方法名相同、参数列表相同（参数不同是重载，不是重写）
两小返回值类型更小（协变返回，可以是子类）、抛出的受检异常更小
一大访问权限不能更小（public 不能改成 protected）
不能重写final、static（静态方法叫隐藏）、private（不可见）、构造器
注解强烈建议加 @Override，编译期帮你校验签名

多态：方法表是怎么找到实现的

多态成立有三个前提：继承/实现 + 方法重写 + 父类引用指向子类对象。但真正让它"跑起来"的，是运行时的动态分派：invokevirtual 指令会去对象头里取实际类型的虚方法表，再查表找到真正的方法地址。

Animal a = new Dog();   // 编译期类型 Animal，运行期类型 Dog
a.speak();
引用 a（栈）
类型声明：Animal
→
堆对象
实际类型：Dog

编译期：编译器只校验 Animal 有没有 speak()。它不知道将来跑什么。

运行期查表　JVM 拿到对象头里的实际类型 Dog，去 Dog 的虚方法表里查 speak。

Dog 的虚方法表
speak()→ Dog.speak ★
eat()→ Animal.eat
toString()→ Object.toString

Dog 重写了 speak，表里指向 Dog 自己的实现；没重写的 eat 仍然指向父类。

命中并调用　执行 Dog.speak()，输出"汪汪"。

Dog 的虚方法表
speak()→ Dog.speak ★ 命中
eat()→ Animal.eat

这就是"编译看左边，运行看右边"。

高频陷阱：成员变量不参与多态

class Animal { String name = "animal"; String getName(){ return name; } }
class Dog extends Animal { String name = "dog"; }

Animal a = new Dog();
System.out.println(a.name);       // animal ← 字段看编译期类型（静态绑定）
System.out.println(a.getName());  // animal ← 方法体里的 name 是 Animal 的字段

字段没有"重写"概念，只有隐藏。所以不要在父类和子类里定义同名字段，这是纯粹的坑。

向上转型与向下转型

  • 向上转型：Animal a = new Dog()，自动、安全，但只能调用父类声明的方法。
  • 向下转型：Dog d = (Dog) a，必须强转，类型不匹配抛 ClassCastException。
  • 先用 instanceof 判断（Java 16+ 可写成 if (a instanceof Dog d)，直接绑定变量）。

06 / ABSTRACT vs INTERFACE

接口与抽象类：怎么选

对比表背下来只是及格；能说出"什么场景用哪个"才是加分项。核心一句话：抽象类表达 is-a（是什么），接口表达 can-do（能做什么）。

维度抽象类 abstract class接口 interface
构造器有，可定义（子类 super 调用）没有，不能实例化
字段任意（含实例变量、可变状态）只能是 public static final 常量
方法抽象方法 + 具体方法都可以抽象方法 / default / static / private（Java 9+）
继承数量单继承（extends 一个）多实现（implements 多个）
访问修饰public / protected / 默认 / private方法默认 public
语义is-a，共享状态与实现can-do，约定能力契约
典型场景模板方法、骨架实现、有公共字段能力扩展、跨继承体系解耦、函数式接口

用抽象类

多个子类共享字段和部分实现，且天然是同一族。
例：AbstractOrderService 里放公共的下单校验、日志、事务模板，子类只实现 doCreate()。

用接口

只想约定能力，实现方可能毫无血缘关系。
例：PayChannel（微信/支付宝/银行卡）、Comparable、Runnable。

Java 8 之后接口的进化

public interface PayChannel {
    boolean pay(BigDecimal amount);              // 抽象方法

    default String channelName() { return "通用渠道"; }   // 默认方法，子类可不实现

    static PayChannel of(String type) { ... }            // 静态方法，接口自己用

    private void log(String msg) { ... }                  // Java 9+，default 方法复用
}
  • default 方法解决了"给接口加方法就破坏所有实现类"的问题（向后兼容）。
  • 菱形冲突：两个接口有同名 default 方法，实现类必须重写，或 InterfaceA.super.method() 显式指定。
  • 函数式接口：只有一个抽象方法的接口，可配合 Lambda，如 Function、Predicate。

一句话选择原则

"需要复用状态/实现用抽象类，需要复用契约用接口；两者都要时，抽象类实现接口，再让子类继承抽象类——这也是 JDK 里 AbstractList 实现 List 的做法。"

07 / PRACTICE

任务 2：订单 / 商品 / 用户模型

把今天的概念落到一个能跑的模型上。目标不是写完整业务，而是让"封装、继承、多态、接口"各自有地方站。

模型关系

User 1 ──< N Order 1 ──< N OrderItem N ──> 1 Product

Order 持有 List<OrderItem>，OrderItem 记录下单时的价格快照（商品调价不影响历史订单）
OrderStatus 用枚举：CREATED / PAID / CANCELLED
PayChannel 用接口 + 多个实现 → 演示多态

关键代码骨架

// ① 枚举：状态用枚举，不用 int 常量
public enum OrderStatus { CREATED, PAID, CANCELLED }

// ② 值对象：金额一律 BigDecimal，禁止 double
public final class Money {
    private final BigDecimal value;
    public Money(BigDecimal v) {
        if (v == null || v.signum() < 0) throw new IllegalArgumentException("金额非法");
        this.value = v.setScale(2, RoundingMode.HALF_UP);
    }
    public Money plus(Money o) { return new Money(value.add(o.value)); }
    public BigDecimal value() { return value; }
}

// ③ 商品：不可变，价格改动只能产生新对象
public record Product(long id, String name, Money price) { }

// ④ 订单项：价格快照
public record OrderItem(Product product, int qty, Money unitPrice) {
    public Money subtotal() { return new Money(unitPrice.value().multiply(BigDecimal.valueOf(qty))); }
}

// ⑤ 多态：支付渠道
public interface PayChannel {
    String name();
    void pay(Order order);
}
public class AliPay implements PayChannel {
    public String name() { return "支付宝"; }
    public void pay(Order order) { /* 调 SDK */ }
}

// ⑥ 订单：封装 + 状态流转
public class Order {
    private final String id;
    private final long userId;
    private final List<OrderItem> items = new ArrayList<>();
    private OrderStatus status = OrderStatus.CREATED;

    public void addItem(OrderItem item) {
        if (status != OrderStatus.CREATED) throw new IllegalStateException("已支付不可修改");
        items.add(item);
    }
    public Money total() {
        return items.stream().map(OrderItem::subtotal)
                    .reduce(new Money(BigDecimal.ZERO), Money::plus);
    }
    public void pay(PayChannel channel) {   // 依赖接口 → 可插拔，运行时决定实现
        channel.pay(this);
        this.status = OrderStatus.PAID;
    }
}

① 创建用户　User u = new User(1001L, "张三")　→ 校验非空。

② 挑选商品　Product p = new Product(2001L, "机械键盘", new Money("399.00"))　→ 不可变值对象。

③ 加入订单项　order.addItem(new OrderItem(p, 2, p.price()))　→ 记录价格快照；状态非 CREATED 会拒绝。

④ 计算总价　order.total()　→ 逐项 subtotal 再 plus，全程 BigDecimal，无精度损失。

⑤ 支付（多态）　order.pay(new AliPay())　→ 传入不同实现，行为不同，Order 无需 if-else 判断渠道。

⑥ 查询　List<Order> list = repo.findByUser(1001L)　→ 返回防御性拷贝，避免外部改内部集合。

钱相关三个硬规定

  • 禁止 double：0.1 + 0.2 != 0.3，二进制浮点存不下十进制小数。
  • 禁止 equals 比较：new BigDecimal("1.0").equals(new BigDecimal("1.00")) 是 false（scale 不同），要用 compareTo。
  • 必须指定 scale 和舍入模式：除法 1/3 不指定会抛 ArithmeticException。

JDK、JRE、JVM 三者的关系？

JVM 是执行字节码的虚拟机（规范 + 实现）；JRE = JVM + 标准类库；JDK = JRE + 开发工具。包含关系是 JDK ⊃ JRE ⊃ JVM。跨平台靠的是字节码 + 各平台各自的 JVM 实现。

Java 是编译型还是解释型？

混合型。javac 先编译成平台无关字节码，JVM 运行时解释执行；热点代码由 JIT（C1/C2 分层编译）编译为机器码。

类加载的五个阶段，静态变量在哪一步赋初值？

加载 → 验证 → 准备 → 解析 → 初始化。准备阶段分配内存并赋零值，初始化阶段执行 <clinit> 才赋代码里的真实初值。

int i = 0; i = i++; 之后 i 是多少？为什么？

0。字节码顺序是 iload_1（把 0 压栈）→ iinc（局部变量变 1）→ istore_1（把栈里的 0 写回，覆盖 1）。i = ++i 才是 1。

Java 是值传递还是引用传递？为什么 swap(int,int) 无效？

只有值传递。基本类型传值的副本，方法内改副本不影响调用方。引用类型传的是地址的副本，所以能通过副本修改堆对象内容，但无法改变原引用的指向。

为什么传对象进去 o = new Order() 无效，o.setX() 有效？

o = new 只改变了副本 o 的指向；o.setX() 是顺着副本里的地址去改堆上的同一个对象。

重写（Override）有哪些规则？

两同（方法名、参数列表）、两小（返回类型协变、受检异常更小）、一大（访问权限不缩小）。final/static/private/构造器不能被重写；建议加 @Override。

父类和子类构造器、静态块、实例块的执行顺序？

父静态块 → 子静态块 → 父实例块 → 父构造器 → 子实例块 → 子构造器。静态块只执行一次。

多态的实现原理？为什么"编译看左边，运行看右边"？

编译期检查引用类型的声明类型是否有该方法；运行期由 invokevirtual 取对象实际类型的虚方法表，查表定位到重写后的实现，实现动态分派。

成员变量为什么不多态？

字段只有"隐藏"，不参与动态分派，访问时按引用变量的声明类型静态绑定。所以 Animal a = new Dog() 时 a.name 取的是 Animal 的字段。

接口和抽象类怎么选？

抽象类用于共享状态与实现（is-a），接口用于约定能力契约（can-do，且可多实现）。两者都要时：抽象类实现接口，子类继承抽象类。

订单金额为什么必须用 BigDecimal？有哪些坑？

double 有二进制精度误差。坑：① 用 equals 比较会因 scale 不同返回 false，要用 compareTo；② 除法必须指定 scale 和 RoundingMode，否则可能抛 ArithmeticException；③ 必须显式 setScale 统一精度。
