03 / SET & MAP

HashSet 就是 HashMap 的键

这是集合框架里最漂亮的设计之一：Set 根本没有自己的数据结构，它把一个 HashMap 包在里面，value 全部塞一个常量。

// HashSet 源码（简化）
public class HashSet<E> implements Set<E> {
    private transient HashMap<E, Object> map;
    private static final Object PRESENT = new Object();  // 所有 value 都是它

    public boolean add(E e) { return map.put(e, PRESENT) == null; }
    public boolean contains(Object o) { return map.containsKey(o); }
    public boolean remove(Object o) { return map.remove(o) == PRESENT; }
    public int size() { return map.size(); }
}

所以 D2 的内容在这里直接生效

HashSet 去重依赖 hashCode + equals。你的元素类如果没重写这两个方法，add 两次同一个内容的对象会成功两次——因为 HashSet 认为它们是不同的 key。

三种 Set，三种顺序

实现底层顺序复杂度适用
HashSetHashMap无序（hash 决定）add/get O(1)只关心去重
LinkedHashSetLinkedHashMap插入顺序O(1) + 额外链表开销去重且要保序
TreeSetTreeMap（红黑树）排序O(log n)需要有序遍历、范围查询

同理 TreeSet 要求元素实现 Comparable 或构造时传 Comparator，否则 ClassCastException。

LinkedHashMap 顺手做一个 LRU

// accessOrder=true：每次 get 把元素移到链表尾部（最近使用）
new LinkedHashMap<K, V>(16, 0.75f, true) {
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > 100;      // 超过 100 就淘汰最久未用的
    }
};

面试常问"怎么实现 LRU"，答这两行就够了；要手写的话是 HashMap + 双向链表。

0 / 4

三个关键常量

16默认初始容量（DEFAULT_INITIAL_CAPACITY），必须是 2 的幂
0.75负载因子（DEFAULT_LOAD_FACTOR），空间与冲突的折中
12阈值 = 16 × 0.75，元素超过 12 就扩容

为什么容量必须是 2 的幂？

因为定位用的是 (n - 1) & hash。n 是 2 的幂时，n-1 的二进制是「全 1」（如 15 = 1111），按位与的结果恰好等于取模，且分布均匀。
如果 n 不是 2 的幂（比如 15），n-1 = 1110，最低位永远是 0，所有奇数下标的桶永远用不到，冲突率翻倍。
所以 new HashMap(17) 会被自动调整为 32（tableSizeFor 向上取最近的 2 的幂）。

为什么负载因子是 0.75？

这是一个经验值：0.5 空间浪费大、1.0 冲突多查询慢。0.75 在两者之间，且能让 size 与容量关系满足泊松分布下链表长度期望值很小。
如果明确知道数据量，直接 new HashMap<>(expectedSize / 0.75f + 1) 可以避免扩容——这也是阿里规约里的建议。

05 / PUT

put 流程：八步走完

这是 D3 的核心考点，面试基本必问。不要背文字，按下面的顺序走一遍逻辑，自然就记住了。

第 1 步 · 算 hash

static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

为什么要异或高 16 位？因为数组长度通常很小，只用到了 hash 的低位。把高位掺进来，能让高位也参与定位，减少碰撞。

第 2 步 · table 为空则初始化

if ((tab = table) == null || (n = tab.length) == 0)
    n = (tab = resize()).length;   // 首次 put 才分配 16

这就是"懒加载"：new HashMap() 时不分配数组，第一次 put 才建。

④ 扩容的代价

时间O(n)，要遍历所有元素重新挂链
内存瞬间需要两份数组，可能触发 Full GC
并发HashMap 非线程安全，并发扩容会丢数据（JDK 7 甚至成环）

实践建议：能预估大小时，用 new HashMap<>((int)(expected / 0.75f) + 1) 一次分配到位。

树化的两个条件（别只记 8）

① 链表长度 ≥ 8（TREEIFY_THRESHOLD）
② table 容量 ≥ 64（MIN_TREEIFY_CAPACITY）
不满足②时，treeifyBin 会改为扩容。因为容量小的时候，扩容打散元素比建树更划算。
另外退化条件：树节点 ≤ 6 时会退回链表（UNTREEIFY_THRESHOLD），留 2 的缓冲避免频繁转换。

07 / ITERATE

遍历与 fail-fast

几乎每个 Java 程序员都踩过这个坑：用增强 for 循环遍历集合，循环体里调 list.remove()，直接抛 ConcurrentModificationException。

① 增强 for 本质是迭代器

for (String s : list) { ... }
// 编译后等价于：
Iterator<String> it = list.iterator();
while (it.hasNext()) { String s = it.next(); ... }

② 迭代器创建时记录 modCount

private int expectedModCount = modCount;  // 快照当前修改次数

modCount 是 ArrayList 的字段，每次 add/remove/clear 都会 ++。

③ 循环里 list.remove() 导致计数不一致

for (String s : list) {
    if (s.equals("b")) list.remove(s);  // modCount++，但 expectedModCount 没变
}
// 下一次 it.next() → checkForComodification() → throw CME

④ 三种正确写法

// 方式一：用迭代器自己的 remove（它会同步 expectedModCount）
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().equals("b")) it.remove();
}

// 方式二：removeIf（Java 8，内部就是迭代器，最推荐）
list.removeIf(s -> s.equals("b"));

// 方式三：收集后统一删 / 用新集合过滤
List<String> keep = list.stream().filter(s -> !s.equals("b")).toList();

⑤ fail-fast vs fail-safe

fail-fastfail-safe
代表ArrayList / HashMapCopyOnWriteArrayList / ConcurrentHashMap
机制modCount 校验，发现不一致立刻抛异常遍历副本 / 弱一致性视图，不抛异常
目的尽早暴露 bug，而不是产生错误结果并发场景下允许边改边遍历

08 / CHOOSE

集合选型决策树

面试问"你平时怎么选集合"，别报菜名，按这几问依次判断。

Q1　存的是键值对吗？

是 → Map（见 Q5）　　|　　否 → 继续 Q2

Q2　需要去重吗？

需要 → Set：只去重用 HashSet，要插入顺序用 LinkedHashSet，要排序用 TreeSet

Q3　有"排队/栈"语义吗？

是 → Queue / Deque：一律优先 ArrayDeque；要按优先级出队用 PriorityQueue

Q4　就是普通有序列表？

ArrayList（默认答案）。只有"迭代器驱动 + 频繁删中间元素"才考虑 LinkedList

Q5　Map 要不要排序 / 顺序 / 并发？

都不要 → HashMap；要插入顺序或 LRU → LinkedHashMap；要按 key 排序 → TreeMap；多线程 → ConcurrentHashMap

三个容易被追问的"不要用"

  • 不要用 Vector / Hashtable：全表 synchronized，性能差，已被并发容器取代。
  • 不要用 Stack：继承自 Vector，也是同步的。用 ArrayDeque 代替。
  • 不要用 Collections.synchronizedList 做高并发：锁的是整个集合，用 CopyOnWriteArrayList 或分段容器。

复杂度速查

结构addremoveget / contains有序
ArrayListO(1)*O(n)O(1)插入顺序
LinkedListO(1)O(1)†O(n)插入顺序
HashSet / HashMapO(1)O(1)O(1)无序
TreeSet / TreeMapO(log n)O(log n)O(log n)排序
ArrayDequeO(1)O(1)—双端

09 / PRACTICE

任务 2：分组统计与 Top-N

这是集合知识最典型的两个业务场景，也是面试手写题的高频来源。围绕 D1 的订单模型来写。

场景一：按用户分组统计消费总额

// 传统写法：merge 是 Map 最被低估的 API
Map<Long, BigDecimal> sumByUser = new HashMap<>();
for (Order o : orders) {
    sumByUser.merge(o.getUserId(), o.getTotal(), BigDecimal::add);
}
// merge 的语义：key 不存在就放 value；存在就用第三个参数合并

// Stream 写法（等价的，可读性更好）
Map<Long, BigDecimal> sum2 = orders.stream()
    .collect(Collectors.groupingBy(
        Order::getUserId,
        Collectors.reducing(BigDecimal.ZERO, Order::getTotal, BigDecimal::add)));
// 或更简单：
Map<Long, BigDecimal> sum3 = orders.stream()
    .collect(Collectors.groupingBy(Order::getUserId,
             Collectors.mapping(Order::getTotal,
                 Collectors.reducing(BigDecimal.ZERO, BigDecimal::add))));

为什么用 merge 而不是 get + put

// 笨写法：两次查表，还要处理 null
BigDecimal old = map.get(uid);
map.put(uid, old == null ? amount : old.add(amount));

// merge：一次查表，语义清晰，且并发 Map 下是原子的
map.merge(uid, amount, BigDecimal::add);

场景二：取金额 Top 3

方案 A · 全排序

orders.sort(Comparator
    .comparing(Order::getTotal).reversed());
List<Order> top3 = orders.subList(0, 3);
复杂度O(n log n)
缺点100 万条数据只为取前 3 名，白排了 99.9997%

方案 B · 小顶堆（推荐）

PriorityQueue<Order> heap = new PriorityQueue<>(
    3, Comparator.comparing(Order::getTotal));
for (Order o : orders) {
    heap.offer(o);
    if (heap.size() > 3) heap.poll();   // 弹出最小的
}
复杂度O(n log k)，k=3 时接近 O(n)
关键求最大 Top-K 要用小顶堆，不是大顶堆

三个容易写错的细节

  • Comparator 方向：求最大 Top-K 用升序比较器（小顶堆）；写成 reversed() 就变成大顶堆，结果反了。
  • PriorityQueue 遍历不保证有序：它只保证 peek()/poll() 有序。直接 for-each 打印出来是乱序，必须反复 poll。
  • null 元素：PriorityQueue 不允许 null，会抛 NPE；比较器里也要防 null 字段。

今天的自测

D3 的题在面试里出现频率最高，尤其 put 流程和选型。

ArrayList 和 LinkedList 怎么选？

默认 ArrayList。它随机访问 O(1)、遍历快、内存省。LinkedList 只在"由迭代器驱动、频繁删除中间元素"时有优势，且 get(i) 是 O(n)。需要栈/队列时用 ArrayDeque，比 LinkedList 更快。

ArrayList 的默认容量和扩容倍数？

默认容量 10，但 new ArrayList<>() 时是空数组，第一次 add 才分配 10。扩容为原容量的 1.5 倍（old + (old >> 1)），通过 Arrays.copyOf 拷贝到新数组。

HashSet 是怎么实现的？

内部持有一个 HashMap，元素作为 key，value 统一是静态常量 PRESENT。所以去重完全依赖元素的 hashCode 和 equals。

HashMap 的底层结构？

JDK 8：数组 + 链表 + 红黑树。数组是主体，哈希冲突时用链表，链表长度 ≥ 8 且容量 ≥ 64 时转红黑树；树节点 ≤ 6 时退回链表。

完整口述 HashMap 的 put 流程？

① 计算 hash：h ^ (h>>>16)；② table 为空则 resize 初始化 16；③ 用 (n-1)&hash 定位桶；④ 桶空就新建节点；⑤ 否则比较首节点 hash 与 equals，相同则覆盖 value；⑥ 是 TreeNode 则走红黑树插入；⑦ 否则遍历链表尾插，途中发现相同 key 则覆盖，插入后链表到 8 尝试树化；⑧ size++，超过阈值 12 则扩容。

为什么 HashMap 的容量必须是 2 的幂？

因为定位用 (n-1) & hash，只有 n 是 2 的幂时 n-1 才是全 1 的掩码，等价于取模且分布均匀；同时扩容时可用 hash & oldCap 判断元素留在原位还是移动 oldCap 位，无需重算 hash。

为什么负载因子是 0.75？

空间与冲突率的折中：0.5 浪费空间，1.0 冲突严重。0.75 是 JDK 团队在大量测试下的经验值。已知数据量时应预先计算容量 expected/0.75+1 避免扩容。

JDK 7 和 JDK 8 的 HashMap 有什么差别？

① JDK 7 头插，JDK 8 改尾插（避免并发扩容成环）；② JDK 8 引入红黑树优化极端冲突；③ JDK 8 的 hash 扰动简化为一次高低 16 位异或（JDK 7 是四次移位异或）；④ JDK 8 扩容用高低位拆分，不再重算 hash。

扩容时元素怎么重新分布？

容量翻倍后，用 (e.hash & oldCap) 判断：为 0 留在原下标 j，否则移到 j + oldCap。把原链表拆成 lo/hi 两条链直接挂到新数组，不需要重新计算 hash。

为什么在 foreach 里 remove 会抛异常？怎么改？

增强 for 底层是 Iterator，创建时把 modCount 快照到 expectedModCount；集合被结构性修改后 modCount 变化，下一次 next() 调用 checkForComodification() 抛 CME。改用 it.remove()、removeIf()，或 CopyOnWriteArrayList。

fail-fast 和 fail-safe 的区别？

fail-fast（ArrayList/HashMap）在遍历中检测到结构性修改立即抛异常，目的是尽早暴露 bug；fail-safe（CopyOnWriteArrayList/ConcurrentHashMap）遍历的是副本或弱一致视图，不抛异常但不保证看到最新数据。

怎么用 LinkedHashMap 实现 LRU？

构造时传 accessOrder=true，让 get 把元素移到尾部；重写 removeEldestEntry，当 size 超过上限返回 true 即淘汰最久未使用的头部元素。

Top-K 为什么用小顶堆？

求最大的 K 个，需要把"当前 K 个里最小的"放在堆顶当守门员：新元素只有比它大才进堆，进来后弹掉堆顶，维持堆内始终是当前的 K 个最大值。时间 O(n log k)，空间 O(k)。

Map 的 merge 方法有什么用？

合并操作的一站式 API：key 不存在则放入 value，存在则用第三个参数（BiFunction）合并旧值和新值。相比 get+put 只查一次表，语义清晰，且在 ConcurrentHashMap 下是原子操作。
