01 / CLASS

Class 对象：类的说明书

JVM 加载一个类时，会在方法区为它生成一份元数据，并在堆里创建一个 Class 对象。反射的本质，就是在运行时读这份说明书并操作它。

三种获取方式

① 类名.class

Class<Order> c = Order.class;

编译期确定，不会触发类初始化，最安全最快。

② 对象.getClass()

Class<?> c = order.getClass();

已有实例时用，返回的是运行时真实类型（可能是子类）。

③ Class.forName("全限定名")

Class<?> c = Class.forName("com.x.Order");

会触发类初始化（执行 static 块），这是 JDBC 驱动加载的经典写法。

④ ClassLoader.loadClass()

cl.loadClass("com.x.Order");

只加载不初始化，延迟到首次使用。

面试陷阱：Class.forName 和 loadClass 的区别

forName 默认 initialize=true，会执行静态代码块；loadClass 只做加载。
老 JDBC 代码写 Class.forName("com.mysql.jdbc.Driver") 就是为了触发驱动类静态块里的 DriverManager.registerDriver(...)。JDK 6 之后 SPI 机制接管了这件事，这行可以省略。

反射能拿到什么

Class<?> c = Order.class;

c.getSimpleName();          // "Order"
c.getSuperclass();          // Object.class
c.getInterfaces();          // 实现的接口
c.getDeclaredFields();      // 本类所有字段（含 private，不含继承）
c.getFields();              // 所有 public 字段（含继承）
c.getDeclaredMethods();     // 本类所有方法（含 private）
c.getDeclaredConstructors();// 所有构造器
c.getAnnotations();         // 运行时可见的注解
c.isInterface(); c.isEnum(); c.isArray();

Declared 的区别要记牢

带 Declared = 本类声明的（包括 private）
不带 Declared = 所有 public 的（包括从父类继承的）
想拿父类的 private 字段？只能 c.getSuperclass() 逐层往上找。

02 / INVOKE

反射调用：四步走

反射调用看着神秘，其实就是四步：找到 Class → 找到成员 → 设置可访问 → 调用。把这四步走一遍，Spring 里所有"魔术"都不再神秘。

① 拿到 Class 对象　这是所有反射的入口。

Class<Order> cOrder.class

② 找到目标成员　字段、方法、构造器分别有对应的 API。

Field f = c.getDeclaredField("amount");
Method m = c.getDeclaredMethod("total");
Constructor<Order> ctor = c.getDeclaredConstructor(String.class);

③ 突破访问控制　private 成员默认不可访问，要 setAccessible(true)。

f.setAccessible(true);   // 关闭访问检查（不是改权限，是跳过检查）

// Java 9+ 模块系统下，跨模块反射私有成员可能抛 InaccessibleObjectException
// 需要目标模块 opens 该包：--add-opens java.base/java.lang=ALL-UNNAMED

这是 JDK 17 之后很多老框架报错的根因。

④ 调用

Order o = ctor.newInstance("1001");   // 相当于 new Order("1001")
f.set(o, new BigDecimal("99.00"));       // 相当于 o.amount = ...
Object r = m.invoke(o);                // 相当于 o.total()
c.newInstance创建对象
→
f.set写字段
→
m.invoke调方法

invoke 的返回值与异常

① invoke 返回 Object，基本类型会被装箱，返回 int 的方法拿到的是 Integer。
② 目标方法抛的异常会被包装成 InvocationTargetException，真实异常在 getCause() 里。不拆包的话，你看不到真正的错误。

03 / COST

反射为什么慢

"反射慢"是面试高频追问。真正的原因不是"它是反射"，而是这四个具体的机制。说清楚这四点，比背"反射比直接调用慢 10 倍"有价值得多。

① 无法内联JIT 看不到目标方法，无法做方法内联——而内联是所有 JVM 优化的前提
② 参数包装调用时要构造 Object[]，基本类型要装箱，返回再拆箱
③ 访问检查每次调用都要做可见性校验（setAccessible(true) 可以跳过）
④ 方法查找getDeclaredMethod 每次都要遍历方法表匹配签名

怎么优化

// ❌ 循环里每次都查一遍方法
for (Order o : list) {
    Method m = Order.class.getDeclaredMethod("total");  // 每次都遍历方法表
    m.invoke(o);
}

// ✅ 把 Method 缓存起来（Spring 就是这么干的）
private static final Method TOTAL = find();
for (Order o : list) TOTAL.invoke(o);

// ✅ 更彻底：MethodHandle（JIT 可见，接近直接调用）
MethodHandle mh = MethodHandles.lookup()
        .findVirtual(Order.class, "total", MethodType.methodType(BigDecimal.class));
mh.invokeExact(o);

准确的表述

"反射的首次调用很慢（要解析、校验），但把 Method 缓存下来之后，性能差距会缩小到几倍以内；如果换成 MethodHandle 或 LambdaMetafactory，可以接近直接调用。真正不能接受的是把反射放在热点循环里反复查找。"

补充：setAccessible(true) 到底做了什么

它不是"提升权限"，而是关闭访问检查（把 override 标志置为 true），让后续调用跳过 Reflection.verifyMemberAccess。所以它不会破坏封装语义，只是省了一次校验。

04 / ANNOTATION

注解：贴在代码上的标签

注解本身不做任何事，它只是元数据。真正让它生效的是"读它的代码"——编译器、注解处理器，或者运行时的反射。

四个元注解决定行为

@Retention保留到哪一阶段：SOURCE / CLASS / RUNTIME（只有 RUNTIME 能被反射读到）
@Target能贴在哪：TYPE / FIELD / METHOD / PARAMETER / CONSTRUCTOR / ANNOTATION_TYPE…
@Documented是否进入 javadoc
@Inherited子类是否继承父类上的注解（只对类注解有效）

① Retention 三档　选错档位，运行时反射什么都读不到。

SOURCE
只在源码中，编译后丢弃。
例：@Override、@SuppressWarnings
CLASS
保留在 .class 但不加载到 JVM，反射读不到。
这是默认值
RUNTIME
保留到运行期，反射可读。
例：@Component、@Test

注意：不写 @Retention 时默认是 CLASS，这是新手最常踩的坑——注解写了，反射却读不到。

② 自己定义一个能被反射读到的注解

@Retention(RetentionPolicy.RUNTIME)    // 关键，不写就是 CLASS
@Target({ElementType.FIELD, ElementType.METHOD})
public @interface Column {
    String value();                  // 注解的"属性"其实是方法
    boolean nullable() default true;  // 可以有默认值
}

③ 使用并读取

class Order {
    @Column("order_no") private String orderNo;
    @Column(value = "amount", nullable = false) private BigDecimal amount;
}

// 读取：
for (Field f : Order.class.getDeclaredFields()) {
    Column col = f.getAnnotation(Column.class);
    if (col != null) System.out.println(f.getName() + " → " + col.value());
}

运行期通过反射读取，Spring 全家桶都走这条路

05 / PRACTICE

任务 2：简易字段映射器

这是 MyBatis / JPA 的核心思路：把数据库列名映射到 Java 字段。写一遍，你就理解了 ORM 为什么能"自动"赋值。

// ① 注解：声明字段对应的列名
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Column { String value(); }

// ② 映射器：把 Map<列名, 值> 填充进对象
public final class RowMapper {

    public static <T> T map(Class<T> type, Map<String, Object> row) {
        try {
            T obj = type.getDeclaredConstructor().newInstance();
            for (Field f : type.getDeclaredFields()) {
                Column col = f.getAnnotation(Column.class);
                if (col == null) continue;
                Object v = row.get(col.value());
                if (v == null) continue;
                f.setAccessible(true);
                f.set(obj, convert(v, f.getType()));   // 类型转换
            }
            return obj;
        } catch (ReflectiveOperationException e) {
            throw new IllegalStateException("映射失败: " + type, e);   // 保留 cause
        }
    }

    private static Object convert(Object v, Class<?> target) {
        if (target.isInstance(v)) return v;
        if (target == BigDecimal.class) return new BigDecimal(v.toString());
        if (target == Long.class)      return ((Number) v).longValue();
        if (target == Integer.class)   return ((Number) v).intValue();
        if (target == String.class)    return v.toString();
        throw new IllegalArgumentException("不支持的类型: " + target);
    }
}

① 输入：一行数据库记录

order_no = "A001"
amount = 99.00
status = "PAID"

② 反射扫描字段，查注解

orderNo@Column("order_no")
→
amount@Column("amount")
→
createTime无注解 → 跳过

③ setAccessible + 类型转换 + set

"A001"String → String
→
field.set写入成功
99.00 → BigDecimal需转换

④ 得到完整对象

Order{ orderNo='A001', amount=99.00, status=PAID, createTime=null }

MyBatis 的 resultMap、JPA 的 @Column，加上缓存和更完善的类型处理，本质就是这个循环。

06 / STATIC VS DYNAMIC

静态代理 vs 动态代理

代理模式的目的：在不改原类的前提下，给方法加上额外逻辑。静态代理手写，动态代理在运行时生成。

静态代理：一个类对应一个代理

interface OrderService { void create(); }

class OrderServiceImpl implements OrderService {
    public void create() { /* 业务 */ }
}

class OrderServiceProxy implements OrderService {
    private final OrderService target;
    public void create() {
        log("before");
        target.create();      // 委托
        log("after");
    }
}

问题：接口有 20 个方法，就要手写 20 次委托——这正是动态代理要解决的。

动态代理：运行时生成代理类

OrderService proxy = (OrderService) Proxy.newProxyInstance(
    cl,                                    // 类加载器
    new Class<?>[]{ OrderService.class },  // 要实现的接口
    (p, m, args) -> {                      // InvocationHandler
        log("before");
        Object r = m.invoke(target, args);  // 反射调用真实方法
        log("after");
        return r;
    });

// 一个 handler 搞定所有方法，这就是 AOP 的原理

07 / JDK PROXY

JDK 动态代理的调用链

这是今天最该讲透的一张图。面试问"动态代理原理"，答的就是这条链：调用代理对象 → 进入 InvocationHandler → 反射调真实方法。

① 生成代理类　Proxy.newProxyInstance 在运行时生成 $Proxy0，它实现了你指定的接口。

$Proxy0运行时生成，实现 OrderService

这个类在磁盘上看不到（可以用 -Djdk.proxy.ProxyGenerator.saveGeneratedFiles=true 导出）。

② 调用代理对象的方法　用户代码写的是 proxy.create()。

client.create()调用方
→
$Proxy0.create()生成的代理方法

③ 代理方法把调用转交给 handler

// $Proxy0 里生成的方法大致是：
public final void create() {
    try { this.h.invoke(this, m3, null); }   // h 就是你传的 InvocationHandler
    catch (Throwable e) { throw new UndeclaredThrowableException(e); }
}
$Proxy0.create()
→
handler.invoke(proxy, method, args)你可以在这里加任何逻辑

④ handler 内部反射调用真实对象

handler.invoke
→
method.invoke(target, args)反射调真实方法

所以动态代理的性能开销 = 一次额外方法调用 + 一次反射调用。这就是为什么 Spring 会缓存 Method。

⑤ 核心限制：只能代理接口

生成的 $Proxy0 已经 extends Proxy，Java 单继承，所以它只能通过 implements 来"成为"你的类型。
如果目标类没有实现接口，JDK 动态代理就无能为力 —— 这正是 CGLIB 存在的理由。

08 / CGLIB

CGLIB：生成子类来代理

思路完全不同：既然不能"实现接口"，那就继承目标类、重写方法，在重写的方法里调父类实现。

JDK 动态代理
原理生成类实现接口
前提目标必须实现接口
局限无法代理没有接口的类
性能生成快，调用稍慢（反射）
依赖JDK 自带
CGLIB
原理生成子类重写方法
前提类不能是 final
局限final 类/方法无法代理；private 方法代理不了
性能生成慢（改字节码），调用快（无反射）
依赖第三方库（Spring 已内置为 spring-core）

Spring AOP 怎么选？

规则很简单：
目标类实现了接口 → 默认用 JDK 动态代理
没有实现接口 → 用 CGLIB
也可以通过 @EnableAspectJAutoProxy(proxyTargetClass = true) 强制 CGLIB。
Spring Boot 2.x 之后默认全局使用 CGLIB（spring.aop.proxy-target-class=true），因为它能代理没有接口的类，且避免了"注入接口却拿到代理对象"的类型困惑。

三个经典坑

  • 自调用失效：同类内部 this.method() 不走代理，所以 @Transactional 失效。解决：注入自身 / AopContext.currentProxy()。
  • final 方法不被代理：CGLIB 无法重写 final 方法，注解加了也没用。
  • private 方法不被代理：子类看不到 private，JDK 代理也代理不到接口外的方法。

09 / IN FRAMEWORK

它们在框架里的位置

这四个例子能让你明白：框架不是魔法，只是把反射 + 注解 + 代理组合得很好。

场景用了什么做了什么
Spring IoC反射 + 注解扫描 @Component，反射创建实例、注入依赖
Spring AOP动态代理为目标 Bean 生成代理，在方法前后织入切面逻辑

MyBatis Mapper 的例子值得单独想一下

// 但你这样用：

10 / SELF CHECK

今天的自测

获取 Class 对象的四种方式，区别是什么？

① 类名.class：编译期确定，不触发初始化；② obj.getClass()：返回运行时真实类型；③ Class.forName(name)：触发类初始化（执行 static 块）；④ classLoader.loadClass(name)：只加载不初始化。

getFields 和 getDeclaredFields 的区别？

getFields 返回所有 public 字段（含继承）；getDeclaredFields 返回本类声明的所有字段（含 private，不含继承）。想拿父类私有字段要沿 getSuperclass 逐层找。

反射为什么慢？怎么优化？

① 无法被 JIT 内联；② 参数要装箱、构造 Object[]；③ 每次调用做访问检查；④ 每次 getDeclaredMethod 要遍历方法表匹配签名。优化：缓存 Method 对象、setAccessible(true) 跳过检查、必要时改用 MethodHandle 或 LambdaMetafactory。

setAccessible(true) 做了什么？

不是提升权限，而是关闭访问检查（把 override 标志置 true），让后续调用跳过 Reflection.verifyMemberAccess 校验。Java 9+ 模块系统下，跨模块反射私有成员可能抛 InaccessibleObjectException，需要 --add-opens。

注解的 @Retention 三档有什么区别？默认是哪档？

SOURCE（编译后丢弃，如 @Override）、CLASS（保留在 class 文件但反射读不到，默认值）、RUNTIME（反射可读，如 @Component、@Test）。写自定义注解想被反射读取，必须显式写 RUNTIME。

注解本身能"执行"逻辑吗？

不能。注解只是元数据，必须由"读取它的代码"来赋予语义：编译器检查（@Override）、注解处理器生成代码（Lombok）、运行时反射读取（Spring）。

静态代理和动态代理的区别？

静态代理在编译期手写代理类，一个实现类对应一个代理，方法多了要重复写委托代码；动态代理在运行期自动生成代理类，用统一的 InvocationHandler 处理所有方法调用，避免重复。

JDK 动态代理的原理？为什么只能代理接口？

Proxy.newProxyInstance 在运行时生成 $Proxy0，它 implements 你指定的接口。调用代理方法时，转发到 InvocationHandler.invoke，再通过 method.invoke 反射调用真实对象。因为 $Proxy0 已经 extends Proxy，Java 单继承，所以只能通过实现接口来"成为"目标类型，无法继承类。

CGLIB 的原理和限制？

通过字节码技术生成目标类的子类，重写非 final 方法，在方法里调用父类实现并织入逻辑。限制：不能代理 final 类、final 方法、private 方法（子类不可见）。

Spring AOP 用哪种代理？

目标类有接口时默认 JDK 代理，无接口时用 CGLIB；Spring Boot 2.x 起默认全部使用 CGLIB（proxyTargetClass=true）。可通过 @EnableAspectJAutoProxy(proxyTargetClass=true) 强制。

为什么 @Transactional 会失效？至少说出三种情况。

① 自调用：同类内部 this.method() 不走代理；② 方法不是 public（Spring AOP 只代理 public）；③ 类是 final 或方法是 final（CGLIB 无法重写）；④ 异常被 catch 吞掉，或抛出的是受检异常但没配 rollbackFor；⑤ 自己 new 出来的对象（不经过容器）。

MyBatis 的 Mapper 接口没有实现类，为什么能调用？

getMapper 返回的是 JDK 动态代理。InvocationHandler 里根据方法名/注解找到对应 SQL，执行后把结果集映射成对象返回。这是"反射 + 注解 + 动态代理"三件套的典型应用。
