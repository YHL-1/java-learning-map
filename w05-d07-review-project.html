04 / STRUCTURE

分层：先有边界，再有功能

项目小，但分层不能省。目的是让"改需求时只改一层"这件事成立。

order-cli/
├── domain/                   // 领域模型，不依赖任何框架
│   ├── Order.java            // 聚合根：id、userId、items、status
│   ├── OrderItem.java        // 价格快照
│   ├── Product.java          // 不可变
│   ├── Money.java            // 值对象，封装 BigDecimal
│   ├── OrderStatus.java      // 枚举
│   └── BizException.java     // 业务异常
├── repo/
│   ├── OrderRepository.java  // 接口（面向接口编程）
│   └── InMemoryOrderRepo.java// 内存实现
├── service/
│   └── OrderService.java     // 编排：校验 → 算价 → 落库
└── cli/
    └── Main.java             // 菜单循环，只做输入输出

为什么 repo 要抽接口

因为 service 不应该知道数据存在哪。现在放内存，将来换 MySQL 只加一个实现类，service 一行不改——这就是 D5 讲的"面向接口 + 代理"思想在业务层的体现。
同时也是 D6 的测试前提：service 的单测可以 mock(OrderRepository.class)，不需要真数据库。

05 / CODE

关键代码走读

这四段是项目的骨架。注意它们分别用到了本周哪一天的知识。

// ① 值对象：D2 的 BigDecimal + D1 的封装
public record Money(BigDecimal amount) implements Comparable<Money> {
    public Money {
        if (amount == null || amount.signum() < 0)
            throw new BizException(ErrorCode.INVALID_AMOUNT);
        amount = amount.setScale(2, RoundingMode.HALF_UP);   // 紧凑构造器里规整
    }
    public Money plus(Money o) { return new Money(amount.add(o.amount)); }
    public Money times(int n) { return new Money(amount.multiply(BigDecimal.valueOf(n))); }
    public int compareTo(Money o) { return amount.compareTo(o.amount); }
}

// ② 实体：D2 的"按 id 判等" + D1 的封装
public class Order {
    private final String id;
    private final long userId;
    private final List<OrderItem> items = new ArrayList<>();  // D3
    private OrderStatus status = OrderStatus.CREATED;

    public void addItem(OrderItem item) {
        if (status != OrderStatus.CREATED)
            throw new BizException(ErrorCode.ORDER_LOCKED);
        items.add(item);
    }
    public Money total() {                       // D2 的 BigDecimal + D3 的 Stream
        return items.stream().map(OrderItem::subtotal)
                    .reduce(new Money(BigDecimal.ZERO), Money::plus);
    }
    @Override public boolean equals(Object o) {   // D2：实体只按 id
        if (this == o) return true;
        if (!(o instanceof Order other)) return false;
        return id.equals(other.id);
    }
    @Override public int hashCode() { return id.hashCode(); }
}

// ③ 服务：D4 的异常 + D6 的可测试性
public class OrderService {
    private final OrderRepository repo;      // 依赖接口 → 可 mock

    public Order create(long userId, List<OrderItem> items) {
        if (items == null || items.isEmpty())
            throw new BizException(ErrorCode.EMPTY_ORDER);
        Order order = new Order(nextId(), userId);
        items.forEach(order::addItem);
        repo.save(order);
        return order;
    }
    public Map<Long, Money> sumByUser() {     // D3 的分组统计
        Map<Long, Money> m = new HashMap<>();
        for (Order o : repo.findAll()) m.merge(o.getUserId(), o.total(), Money::plus);
        return m;
    }
}

// ④ 测试：D6
@Test void emptyItemsShouldThrow() {
    var service = new OrderService(mock(OrderRepository.class));
    assertThrows(BizException.class, () -> service.create(1L, List.of()));
}

12:00 – 15:00　测试与改进方向
"service 用 Mockito mock 掉 repo，覆盖了正常创建、空订单、金额非法三个场景。下一步想换成 JPA 实现，再补集成测试。"

07 / QUICK Q

10 道本周快问快答

每题限时 30 秒。答不出来的就是今天的补课清单。

Q1　JDK、JRE、JVM 的关系？

JDK ⊃ JRE ⊃ JVM。JVM 执行字节码，JRE = JVM + 标准类库，JDK = JRE + 开发工具。跨平台靠字节码 + 各平台各自的 JVM 实现。

Q2　Java 只有值传递，怎么证明？

swap(int,int) 交换后调用方变量不变，因为传的是副本。引用类型传的是地址的副本，所以能改对象内容（o.setX 生效），但改不了原引用（o = new 无效）。

Q3　重写 equals 为什么必须重写 hashCode？

HashMap 先用 hashCode 定位桶，再用 equals 比较。hashCode 不同会落到不同桶，equals 根本没机会执行，导致"相等的对象存进去取不出来"。

Q4　String 为什么不可变？

线程安全可共享、hashCode 可缓存、常量池才能复用、传参不会被篡改。实现上靠 final class + final 字段 + 不暴露内部数组。

Q5　Integer 缓存的坑？

-128~127 走 IntegerCache，同一个对象，== 为 true；超出范围每次 new，== 为 false。比较包装类一律用 equals。

Q6　HashMap put 的八步？

算 hash → table 空则初始化 16 → (n-1)&hash 定位桶 → 桶空就放 → 首节点 hash/equals 相同则覆盖 → TreeNode 走红黑树 → 否则遍历链表尾插（到 8 尝试树化）→ size++ 超阈值 12 则扩容。

Q7　为什么容量必须是 2 的幂？

因为用 (n-1)&hash 定位，n 为 2 的幂时 n-1 是全 1 掩码，等价取模且分布均匀；扩容时还能用 hash&oldCap 判断升降位，无需重算 hash。

Q8　泛型擦除带来哪些限制？

不能 new T()、new T[]、instanceof T、T.class；静态成员不能用 T；f(List<String>) 和 f(List<Integer>) 不能重载（name clash）。

Q9　JDK 动态代理为什么只能代理接口？

生成的 $Proxy0 已经 extends Proxy，Java 单继承，只能通过 implements 成为目标类型。所以没有接口的类要用 CGLIB 生成子类。

Q10　Maven 依赖冲突怎么排查？

dependency:tree 看实际版本，找到引入旧版的依赖加 exclusions，或在 dependencyManagement 里统一锁定版本。运行时 NoSuchMethodError 通常就是低版本覆盖了高版本。
