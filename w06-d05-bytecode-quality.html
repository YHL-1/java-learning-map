02 / CLASS FILE

class 文件：十段结构

不用背全部，但要知道"魔数、常量池、方法表"这三个的位置——面试问"class 文件长什么样"就靠它。

顺序内容说明
1CAFEBABE魔数，固定值，JVM 用它确认"这是个 class 文件"
2minor / major version版本号，Java 8=52，17=61，21=65。高版本不能被低版本 JVM 加载
3常量池字面量 + 符号引用（类名、字段名、方法名、描述符）
4访问标志public / final / interface / abstract …
5this / super当前类、父类的常量池索引
6接口表实现了哪些接口
7字段表字段名、描述符、访问标志、属性
8方法表方法名、描述符、Code 属性（真正的字节码指令）
9属性表Signature（泛型签名）、Exceptions、SourceFile 等

两个名字别搞混

魔数CAFEBABE，0xCAFEBABE，James Gosling 起的"咖啡宝贝"梗
描述符用符号表示类型：I=int、Ljava/lang/String;=String、[I=int[]、(I)Ljava/lang/String;=接收 int 返回 String 的方法

03 / JAVAP

用 javap 看字节码

// 源码
public class Demo {
    public int add(int a, int b) { return a + b; }
}

// javap -c Demo.class
public int add(int, int);
  Code:
     0: iload_1        // 把第 1 个参数 a 压栈
     1: iload_2        // 把第 2 个参数 b 压栈
     2: iadd           // 弹出两个，相加，结果压栈
     3: ireturn        // 返回栈顶的 int

常用参数

-c反汇编，显示字节码指令
-vverbose，显示常量池、版本号、访问标志等全部信息
-p显示 private 成员（默认只显示 public/protected）
-l显示行号表和局部变量表
-s显示签名（描述符）

一个实用场景：直接看编译器怎么"翻译"你的语法糖。

// 源码：foreach
for (String s : list) { ... }

// javap -c 之后：
Iterator it = list.iterator();
while (it.hasNext()) { String s = (String) it.next(); ... }

04 / NEW

为什么 new 是三条指令

这是字节码部分最高频的面试题。答案是：new 只负责分配内存，不负责初始化。

// 源码
Order o = new Order();

// 字节码（4 条，因为还要存到局部变量）
0: new           #2      // 1. 分配内存，压入"未初始化对象"的引用
3: dup                   // 2. 复制栈顶引用（因为下一步会消耗一个）
4: invokespecial #3      // 3. 调用构造器 <init>，消耗掉那个副本
7: astore_1              // 4. 把剩下的引用存进局部变量 o

① new：分配 + 压栈

在堆上分配内存，所有字段赋零值（这就是"对象内存布局"里的初始状态），然后把指向这块内存的引用压入操作数栈。

此时对象还没"构造完成"，但引用已经存在了。

② dup：为什么要复制

因为 invokespecial 调用构造器时，会消耗栈顶的引用（作为 this）。如果只有一个引用，调用完就没了，后面就没法赋值给变量 o。

所以先复制一份：一份给构造器用掉，一份留给 astore。

栈: [ref]
dup →
栈: [ref, ref]

③ invokespecial：执行构造器

调用 <init>，执行字段初始化和构造器体。它会弹出一个引用作为 this，剩下的那个还在栈上。

所以"对象创建"其实分两半：new 分配 + <init> 初始化。这也是 DCL 单例需要 volatile 的根源——引用赋值可能早于初始化完成。

④ astore_1：存进局部变量表

把栈上剩下的引用存到第 1 个槽位（0 号是 this，静态方法从 0 开始）。

一句话回答面试："new 只分配内存并把引用入栈，dup 是为了给构造器留一份，invokespecial 执行 <init> 完成初始化，最后 astore 存入局部变量。"

05 / INVOKE

五条方法调用指令

指令调用场景分派方式
invokestatic静态方法静态绑定
invokespecial构造器、private、super 调用静态绑定
invokevirtual普通实例方法动态分派（查 vtable）
invokeinterface接口方法动态分派（查 itable）
invokedynamicLambda、字符串拼接（Java 9+）运行时绑定 CallSite

这解释了 W05 D1 的多态

"编译看左边，运行看右边"的底层就是：invokevirtual 在运行时从对象头取实际类型的方法表（vtable），再查表找到真正的方法地址。

所以字段不参与多态——字段访问用的是 getfield + 常量池里的符号引用，没有查表这一步。

为什么 Lambda 用 invokedynamic

因为 Lambda 表达式在编译时不生成内部类，而是留一个 invokedynamic 指令，在第一次执行时由 LambdaMetafactory 生成实现类并绑定。

好处：启动更快（不用编译期生成大量类）、实现更灵活。代价：第一次调用有额外开销（可以用 -Djdk.internal.lambda.dumpProxyClasses 看生成的类）。

06 / CONSTANT POOL

常量池：符号引用与直接引用

class 文件里所有"名字"都存在常量池里。类加载的"解析"阶段，就是把这些符号引用换成内存里的直接引用。

// 源码
System.out.println("hello");

// 字节码
0: getstatic     #2   // Field java/lang/System.out:Ljava/io/PrintStream;
3: ldc           #3   // String hello
5: invokevirtual #4   // Method java/io/PrintStream.println:(Ljava/lang/String;)V

#2 #3 #4 是什么

常量池的索引。#4 指向一个 Methodref，里面记录着"类名 + 方法名 + 描述符"——这就是符号引用，它只是字符串，还不知道方法在内存的哪个地址。

类加载的解析阶段会把它换成真正的内存地址（直接引用），之后调用就不用再查了。

这解释了三个常见报错

NoClassDefFoundError解析阶段找不到常量池引用的类
NoSuchMethodError类找到了，但方法签名对不上（通常是依赖版本冲突）
NoSuchFieldError字段对不上，同样常见于版本冲突

字符串常量池 ≠ class 常量池

这两个经常被混为一谈：

class 文件常量池运行时常量池字符串常量池
位置.class 文件里方法区（元空间）堆
内容字面量 + 符号引用加载后放进去的常量String 字面量对象
谁用编译期运行期intern()、== 判断

双亲委派：先问爸爸，爸爸不行再自己来

protected Class<?> loadClass(String name, boolean resolve) {
    synchronized (getClassLoadingLock(name)) {
        Class<?> c = findLoadedClass(name);        // ① 已加载？
        if (c == null) {
            try {
                if (parent != null) c = parent.loadClass(name, false);   // ② 委派父
                else            c = findBootstrapClassOrNull(name);
            } catch (ClassNotFoundException e) { }
            if (c == null) c = findClass(name);   // ③ 父加载不了，自己来
        }
        return c;
    }
}

两个经常答错的地方

目的首要目的是避免类重复加载（保证同一个类在 JVM 里唯一），安全只是附带效果
方向"父优先"，不是"父垄断"。父加载不了（findClass 抛异常）才由自己加载

08 / QUALITY

代码质量：四个工具各管一段

工具查什么典型问题能否自动修
Checkstyle格式与规范缩进、命名、import 顺序、Javadoc 缺失大多能
PMD编码坏味道未使用的变量、空的 catch、过长方法、重复代码部分
SpotBugs字节码级缺陷NPE 风险、equals/hashCode 不一致、资源未关闭不能，但准确率高
SonarQube综合（上面三个 + 覆盖率 + 重复率）技术债、安全漏洞部分

SpotBugs 为什么能发现 NPE

因为它分析的是字节码，能看到真实的控制流。比如：

String s = map.get(key);      // 可能返回 null
if (s.length() > 0) { ... }   // SpotBugs: Possible null pointer dereference

它不需要运行代码，靠数据流分析推断"这条路径上 s 可能是 null"。

Maven 里接入

<plugin>
  <groupId>com.github.spotbugs</groupId>
  <artifactId>spotbugs-maven-plugin</artifactId>
  <version>4.8.3.0</version>
  <configuration>
    <effort>Max</effort>
    <threshold>Low</threshold>      <!-- 报所有级别 -->
    <failOnError>true</failOnError> <!-- 有问题就构建失败 -->
  </configuration>
  <executions>
    <execution>
      <phase>verify</phase>       <!-- 在 verify 阶段跑 -->
      <goals><goal>check</goal></goals>
    </execution>
  </executions>
</plugin>

接入策略建议

不要一上来就 failOnError=true——老项目会有几百个警告，直接阻断构建没人受得了。
正确做法：先只报告不阻断（生成 HTML 报告），挑出高危规则（NPE、资源泄漏、equals 不一致）逐步清零，最后再开启阻断。

09 / SELF CHECK

今天的自测

class 文件的魔数是什么？有什么用？

CAFEBABE（0xCAFEBABE）。JVM 加载时先读这 4 个字节确认是合法的 class 文件，防止把其他格式的文件误当字节码解析。

Java 8 / 17 / 21 的 class 版本号分别是多少？

52 / 61 / 65。高版本编译的 class 不能被低版本 JVM 加载，会抛 UnsupportedClassVersionError。

为什么 new 需要 dup 指令？

因为 invokespecial 调用构造器时会消耗栈顶的引用作为 this。先 dup 复制一份，一份给构造器用掉，一份留给 astore 存入局部变量。

对象创建分哪两步？这和 DCL 单例有什么关系？

new 分配内存（字段赋零值）+ invokespecial 执行 <init>。这两步可能被指令重排——引用赋值可能早于构造完成。DCL 单例如果没有 volatile，其他线程可能拿到未初始化完的对象。

五条方法调用指令分别对应什么场景？

invokestatic（静态方法）、invokespecial（构造器/private/super）、invokevirtual（普通实例方法，动态分派）、invokeinterface（接口方法，动态分派）、invokedynamic（Lambda、字符串拼接）。

为什么 Lambda 用 invokedynamic 而不是内部类？

避免编译期生成大量内部类（启动更快、体积更小），由 LambdaMetafactory 在第一次执行时动态生成实现并绑定 CallSite。代价是首次调用有额外开销。

符号引用和直接引用有什么区别？

符号引用是常量池里的"字符串描述"（类名+方法名+描述符），还不知道内存地址；直接引用是解析后得到的真正内存地址或偏移量。类加载的解析阶段就做这个转换。

NoClassDefFoundError 和 NoSuchMethodError 分别是什么阶段的问题？

都发生在链接/解析或运行时。NoClassDefFoundError 是找不到类（编译时存在、运行时缺失）；NoSuchMethodError 是类找到了但方法签名不匹配，通常是依赖版本冲突导致。

class 常量池、运行时常量池、字符串常量池有什么区别？

class 常量池在 .class 文件里（字面量+符号引用）；运行时常量池在方法区，是 class 常量池加载后的形态；字符串常量池在堆里，专门存 String 字面量对象，供 intern 和 == 使用。

Checkstyle、PMD、SpotBugs 各查什么？

Checkstyle 查格式规范（缩进、命名、import）；PMD 查编码坏味道（空 catch、未用变量、过长方法）；SpotBugs 分析字节码查真实缺陷（NPE、资源泄漏、equals/hashCode 不一致）。三者互补。

静态检查工具一上来就 failOnError 有什么问题？

老项目通常有几百个历史警告，直接阻断会让所有人无法提交。应该先只报告、挑选高危规则逐步修复，最后再开启阻断。
